Graded Assignment: A Simple DNS Client

In a single source file called dnslookup.c, write a C program to query the Domain Name System (DNS). The program must operate as a DNS client, meaning that it must issue a DNS request to a given DNS resolver and then receive the corresponding response. The program must then print the relevant data obtained from the response onto the standard output. The program should behave in a similar way as the dig or the nslookup utilities. The address of the resolver and the query (as well as other parameters) are given as command-line arguments. The general usage of the program should be as follows: 

Usage: ./dnslookup [options] <query> [TYPE]

Arguments:
 query    The DNS query to solve
 TYPE     The DNS record type for the query. Supported values are:
          A, AAAA, MX, CNAME, NS, TXT (default: A)

Options:
 -s <server>, --server <server>
                   The IPv4 address of the DNS resolver (default: 127.0.0.53)
 -r <retries>, --retries <retries>
                   The maximum number of retries before declaring failure (default: 3)
 -t <timeout>, --timeout <timeout>
                   The timeout for receiving the DNS reply in seconds (default: 1s)
 -h, --help
                   Display this help and exit

The program must allow the user to submit a single query. The type of the query is A, AAAA, MX, CNAME, NS or TXT. The default type is A.

The purpose of this exercise is to learn how to operate directly with network packets and with a specific application-level protocol such as DNS. Therefore, you are not allowed to use any of the UNIX standard functions for address resolution, such as getaddrinfo, nor any other external library. Instead, you must explicitly create properly formatted DNS messages, parse incoming DNS messages, and exchange such messages with the given DNS resolver through a standard UDP socket.

You may assume that the resolver is recursive, so you are not required to implement the full, iterative DNS resolution protocol. For the formatting of DNS messages, you may refer to RFC 1035 and RFC 3596. You are not required to implement DNS extensions. You may also assume that the reply is not truncated.

The program must handle communication failures at least to a minimal extent. In particular, if the program does not receive an answer from the resolver, the program must resubmit the same query. The -r or --retries command-line option determines the maximum number of attempts. By default, the program reissues the same query at most three times. The program determines that a request or the corresponding reply were lost after a set timeout. The timeout can be set using the the -t or --timeout command-line options. The dafult timeout is one second. You can implement a timeout mechanism by using the select family of functions, or by setting a timeout option on the socket through with the setsockopt function.

By default, the address of the DNS resolver must be 127.0.0.53. The reason is that systems with systemd-resolved have a DNS resolver for local applications listening on a the address 127.0.0.53 (see the systemd-resolved man pages). The user should also be able to specify the IPv4 address of a DNS resolver with the -s or --server command-line options.

Once it receives a response from the DNS resolver, the program must display the content of the DNS response message by printing the relevant information onto the standard output. The type of information is defined by the structure of the DNS reply as specified in the standard documentation (RFC 1035). In essence, a DNS message contains zero or more entries in each of four sections, namely questions, answers, name servers, and additional records. The program must first print a summary of the DNS reply. The, for each non-empty section, the program must print all the entries in that section. The output format is defined by-example in the following use cases.

The output of a DNS query for a record of type A on google.com must look as follows: 

$ ./dnslookup google.com A 
QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0

QUESTION SECTION:
google.com.             IN      A

ANSWER SECTION:
google.com.     179     IN      A       142.251.140.110
